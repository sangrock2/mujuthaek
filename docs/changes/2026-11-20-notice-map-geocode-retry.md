# 공고 지도 좌표의 정확한 매칭과 자동 복구

공고 주소를 조회했다가 실패하면 공고가 다시 발행돼도 같은 주소의 NOT_FOUND 결과가 남을 수 있었다. 검색 API의 답변에 주소가 비슷한 다른 건물 한 곳만 오면 도로명이나 건물번호 조건을 건너뛰고 그 건물을 채택할 수도 있었다.

붙여 쓴 서울 주소와 시도 별칭을 정리하고, 주소 검색에는 도로명과 건물번호 또는 법정동과 지번을 사용한다. 검색 결과는 공고 주소의 본번·부번·지하 또는 산 여부와 비교한다. 지역 코드가 있다면 일치해야 한다. 전체 결과에서 하나의 출입구만 확인할 수 있을 때 채택한다. 이전의 검색 결과를 새 규칙의 주소 캐시와 섞지 않는다.

좌표 API가 돌려준 출입구도 행정구역코드·도로명코드·지하 여부·본번·부번을 요청한 건물과 대조한다. 식별자가 일치한 한 행의 유한한 좌표만 변환한다. [행정안전부 좌표 API 항목](https://www.data.go.kr/data/15056663/openapi.do)

서버는 15분마다 최대 5곳의 실패 위치를 별도 실행에서 다시 확인한다. 접수 전·접수 중·상시 접수 공고를 먼저 확인한다. 일시 API 오류는 1시간, 검색 결과 없음은 1일, 번호가 있는 주소의 파싱 실패는 7일 이후 대상이 된다. 기존 주소 API의 호출 제한을 적용한다. 주소가 없거나, 후보가 모호하거나, 경계가 맞지 않으면 자동으로 건물 핀을 만들지 않는다. 정확한 좌표가 추가되면 해당 위치의 생활권 정보도 계산한다. 되찾은 좌표는 재조회 시작 당시의 위치 버전과 예약이 일치하고, 해당 공고가 그 버전으로 공개 중일 때만 저장한다. 원래 공고의 공개·검수 상태와 원문은 이 과정에서 바뀌지 않는다.

운영에서 재조회만 끄려면 `mujuthaek.area.geocode.retry-enabled=false`를 설정한다. 지도 검색의 주소 일치 검증은 계속 적용된다.
