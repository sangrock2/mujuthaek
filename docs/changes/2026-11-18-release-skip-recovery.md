# 선택 검사 뒤 배포 생략 문제

## 실제 현상

Production 실행 44292941145는 전체 결론이 success였지만 frontend-prepare만 성공하고 backend-apply·frontend-promote·finalize가 skipped였다. 후보 생성은 실제 서비스 적용이 아니다. 공개 혜택 화면에서 이전의 날짜·0건 안내 문구가 보이는 것을 확인해 실제 미반영을 발견했다. 앞서 실행 성공을 운영 반영 완료로 판단한 보고를 정정한다.

수집기 마이그레이션·이미지 전환은 별도 확인한 호스트 절차로 실제 완료됐다. 지도 45개 복구와 공개 API 확인, main CodeQL 19건 정리(코드 보완 3·근거 분류 16)도 이 배포 생략과 구분한다.

## 원인과 수정

선택 CI에서 불필요한 contracts-check 등이 생략된 뒤, always()로 실행한 ci-check·frontend-prepare는 성공했지만 다음 단계에 명시적 상태 함수가 없었다. GitHub Actions의 기본 success()가 생략된 선행 경로에 영향을 받아 실제 적용 단계까지 생략했다.

- backend-apply와 frontend-promote에 always()·!cancelled() 및 직접 선행 단계의 성공·plan deploy=true 조건을 명시한다.
- 검사·계획·후보가 실패하거나 취소되면 적용하지 않는다. 성공 조건을 넓혀 실패한 검사 뒤 배포하게 만들지 않는다.
- 마지막 Release complete 작업은 배포 대상이 있으면 준비·적용·승격·확정의 성공을 모두 요구한다. 후보만 만든 실행, 실패·취소·생략·증거 누락은 실패한다. 런타임 변경이 없을 때만 단계 생략을 정상으로 인정한다.
- OIDC·Vercel 환경·토큰·프로젝트·체크아웃 자격증명·릴리스 불변 기록과 조건부 S3 포인터 검증은 유지한다.

## 검증

새 배포 게이트 관련 6개 대상 검사가 통과했다. 실제와 같은 후보만 성공한 실행 거절, 각 단계의 실패·취소·생략, 정상 배포, 변경 없음, 증거 누락을 포함한다. 배포 작업이 명시적 상태 함수와 선행 성공을 확인하는지도 검사한다.

기존 #188의 API·Actions 검사는 성공한 상태로 병합하고, 이 수정은 별도 PR에서 배포 흐름·인프라 검사만 수행한다. 동일 API 소스의 전체 검사를 이 수정 때문에 수동으로 반복하지 않는다. 후속 main 릴리스의 실제 적용·Vercel 승격·완료 포인터·운영 화면 확인으로 복구를 마무리한다.
