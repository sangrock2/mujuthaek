# PDF 처리와 관리자 검수 조회 분리

init 적용으로 좀비 500개를 제거한 뒤에도 PDF 해석 중 검수 목록·상세 요청이 시간 초과되는 현상을 확인했다. DB 잠금은 없었고, 비차단 스택 검사에서 같은 Python 프로세스의 PDF 작업 스레드가 `pdfplumber`의 글자 중복 제거를 실행하고 있었다. 승인된 30초 이내 CPU 0.15→0.50 비교에서도 조회가 복구되지 않았으며 즉시 0.15로 복원했다.

PDF 본문·표 해석과 그림 쪽 확인을 별도 Python 자식에서 실행한다. 문서당 입력 50MiB, 결과 16MiB, 실행 시간 180초, 동시 파서 1개로 제한한다. Linux 자식에는 주소 공간 768MiB·CPU 시간 30초·파일 크기 16MiB·코어 덤프 금지를 추가한다. 시간·크기 초과 시 자식을 종료하고 반드시 회수한다. 임시 원문과 결과는 작업 종료 시 제거하며, 자식 환경에는 DB·AWS·AI 자격증명을 전달하지 않는다. 이 조치는 동일 UID 파일 접근까지 격리하는 컨테이너 경계를 뜻하지 않는다.

한도 초과·손상 문서는 기존 읽기 실패 경로로 넘긴다. 표의 병합 칸(`filled`)·열 제목·쪽 번호·2단 구조를 자식 결과에 보존한다. 저장용 `to_json()`은 병합 칸을 생략하므로 프로세스 간 전달에는 사용하지 않는다. 그림 쪽 결과 캐시는 PDF 원문 대신 해시만 유지한다.

## 검증

PDF 본문·표·병합·2단 구조 기존 검사 24건과 자식 시간 초과·출력 초과·환경 비밀 차단·회수/임시 파일 정리·입력 제한 검사 4건 통과. 수정 후 자식 검사와 PDF 위치 근거 검사 13건 통과. 변경 파일 Ruff·형식 검사 통과. 실제 유료 AI 호출은 사용하지 않았다. 운영 적용 및 부하 중 조회 검증은 별도 기록하며, 전체 서비스 테스트는 직접 실행하지 않았다.
