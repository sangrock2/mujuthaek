# 외부 공격 관점 보안 검토 — 2026-11-16

대상은 인터넷에서 접근하는 비로그인 공격자, 정상 계정을 악용하는 공격자, 토큰 사본을 가진 공격자, 수집 원문을 조작할 수 있는 공격자입니다. 운영 서버에 대량 요청·포트 스캔·취약점 스캐너를 실행하거나 실제 사용자 데이터를 가져오지 않습니다. 아래 검증은 격리된 DB·브라우저와 loopback에만 바인딩한 Nginx·합성 upstream으로 수행합니다. 유료 AI를 호출하지 않습니다.

## 확인한 문제와 변경

| 진입점 | 이전 상태·공격 전제 | 변경·검증 |
| --- | --- | --- |
| 공개 채팅 SSE | 인증 없이 연결할 수 있고 hub에 전체·방별 연결 수 상한이 없음. 유효한 공개 공고 ID로 연결을 반복하면 emitter·연결이 누적될 수 있음 | hub 전체 128·방별 32개를 원자적으로 제한. 동시 가입 64개 경합 검사, 종료·타임아웃 중복 시 정확히 한 번 예산 반환. Nginx SSE 전체 상한은 별도로 48개 |
| 일반 API | OAuth 시작 경로에만 속도 제한이 있고 일반 API에는 없음. 모든 API가 버퍼링 없이 1시간 응답 대기를 사용 | 실제 TCP 상대 IP별 20r/s·burst 60, 서버 전체 60r/s·burst 120. 전체 처리 중 연결 96·상대 IP별 64. 일반 upstream 응답 대기는 60초, SSE만 1시간 |
| 원문 다운로드 | 공개 파일을 반복해서 읽는 요청에 별도 예산 없음 | 공고·관리자 PDF 경로 전체 2r/s·burst 6, 동시 전송 8개. 다른 API와 공유하는 상위 제한도 유지 |
| 요청 본문·느린 연결 | 본문 10MiB, 기본 대기 설정 | 본문 1MiB, 헤더·본문 읽기 대기 10초, 송신 대기 30초·keepalive 15초. 본문 제한 초과는 앱 도달 전 413 |
| 게이트웨이 로그 | Nginx 기본 로그의 전체 요청 문자열에 OAuth code·state·인증 링크 쿼리가 기록될 수 있음. 로그를 읽을 수 있어야 노출되는 위험이며 외부 유출을 재현한 것은 아님 | HTTPS 접근 로그를 쿼리·쿠키·Authorization 없이 경로·상태·제한 결과·시간만 JSON으로 기록. 쿼리를 포함하는 일반 error 로그 대신 critical 오류와 접근 로그로 진단. 애플리케이션을 제공하지 않는 HTTP/ACME 리스너는 접근 로그를 끔. 합성 비밀값이 stdout·stderr에 없는지 확인 |
| 앱 프로세스 | 기존에도 non-root·no-new-privileges·메모리 상한 적용 | 앱 컨테이너의 Linux capability 전체 제거, PID 512개 제한. API Tomcat 작업 스레드 64·대기열 32·연결 256으로 한정. 컨테이너 탈출을 완전히 차단하는 것은 아님 |

IP는 **사용자 IP가 아니라 Nginx와 실제 연결한 상대**입니다. Vercel 경유 사용자는 같은 IP를 공유할 수 있어 이를 사용자별 제한이라고 표현하지 않습니다. 공격자가 보낸 `X-Forwarded-For`로 제한 키를 만들지 않습니다. 위 값은 현재 소규모 단일 서버를 위한 초기 방어 예산이며 성능 시험으로 산정한 최대 수용량이 아닙니다. 정상 요청의 429·지연을 관찰해 조정해야 합니다.

## 기존 방어를 공격 입력으로 확인하는 범위

- SQL 검색: 연산자·주석·따옴표·LIKE `%`·`_`·역슬래시를 데이터로 처리하는 실 DB 회귀 검사. 결과가 비어 있고 정상 조회가 계속 동작해야 합니다. 모든 SQL 경로의 무결함 증명은 아닙니다.
- 저장된 HTML: 실제 준비함 API에 `<img ... onerror=...>` 형태의 합성 제목을 저장하고 브라우저에서 텍스트 표시·DOM 이미지 부재·실행 표식 부재를 확인합니다. 기존 React 이스케이프 검증이며 XSS를 발견·수정했다고 세지 않습니다.
- SSRF: 사설·메타데이터 IP, 혼합 DNS 응답, DNS 재바인딩, 리다이렉트, IPv6 전환 주소 및 대체 IPv4 표기 검사. URL 파서가 먼저 거부하는 경우도 정상 차단이며, 네트워크 연결 전에 거부해야 합니다. 기존 transport의 DNS 고정과 TLS 호스트 검증을 유지합니다.
- 인증·관리자: 앞선 보안 PR의 토큰 재사용·즉시 폐기, 소유권·권한 회수, 비신뢰 CORS 검사와 연결합니다. 공개 채팅의 익명 읽기 자체를 권한 우회로 분류하지 않습니다.
- HTTP 경계: 실제 Nginx에 위조 전달 헤더, 내부·관리 경로, 큰 Content-Length, Content-Length/Transfer-Encoding 중복 프레이밍을 보냅니다. 차단된 요청은 합성 upstream에 도달하지 않아야 합니다.

## 재현과 증거

`python3 backend/infra/security/test_gateway.py`는 사용자 지정 대상 URL을 받지 않습니다. 일회용 인증서를 생성하고 테스트 전용 Docker 컨테이너와 upstream을 `127.0.0.1`에만 열어 실행 후 제거합니다. 실제 운영 Nginx 설정에서 listen·upstream·인증서 마운트만 바꿉니다. 한 번에 96개 이하의 짧은 요청 또는 48개의 가벼운 SSE를 사용하며 운영 자격 증명을 읽지 않습니다. 사용한 합성 쿼리 값은 결과 artifact에 출력하지 않습니다.

CI의 `nginx adversarial checks (loopback only)`는 `Checks / CI ready`에 포함됩니다. `gateway-security-evidence` artifact에는 실제 성공한 검사 이름·결과만 남습니다. Java 연결 경합·검색 검사는 API CI, 브라우저 HTML 검사는 E2E CI에서 실행합니다. 실패를 무시하거나 검사 성공 전에 운영 반영 완료라고 기록하지 않습니다. 이번 검토에서는 운영 장애나 침해를 실제로 일으켜 재현하지 않았습니다.

## 운영에서 확인할 것과 남은 한계

1. 게이트웨이 JSON 로그의 `status=429`, `rate=REJECTED`, `connections=REJECTED`, 5xx·응답 시간을 확인합니다. 차단된 요청은 Spring에 도달하지 않으므로 앱 관리자 통계만으로 공격량을 판단하면 안 됩니다. 이 로그에 대한 자동 보안 경보는 아직 별도입니다.
2. 인증·세션과 기본 페이지·PDF·SSE의 정상 흐름, 컨테이너의 적용 capability·PID·스레드 설정을 배포 후 확인합니다. 실제 운영에서 상한을 채우는 공격 시험은 하지 않습니다.
3. 애플리케이션 요청 제한으로 네트워크 대역폭·TLS 핸드셰이크 대량 공격·대규모 분산 DDoS를 막았다고 주장하지 않습니다. 공격자는 여러 IP로 전체 예산을 채워 정상 사용자도 거부되게 할 수 있습니다. 서비스 가용성·분산 공격 흡수에는 상위 네트워크/엣지 방어가 필요합니다.
4. 속도·동시성 제한은 일·월 비용의 절대 상한이 아닙니다. AWS 비용·크레딧 알림은 계속 필요하며 OpenAI 분석 예산과도 별개입니다. 장시간 분산 다운로드, 로그인 봇의 출처 분산, 검증된 정상 계정의 기능 악용은 추가 관찰 대상입니다.
5. PDF·HWP 파서 전체의 프로세스 자원 격리, AI 의미 조작 평가, OS·컨테이너 이미지 취약점과 관리자 MFA·root 대체, 공급자 WAF 정책·보안 경보·복구 훈련은 남은 작업입니다. read-only filesystem·네트워크 분리는 필요한 쓰기·통신을 확인한 뒤 별도로 도입해야 합니다.
